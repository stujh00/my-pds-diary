# 일반 계획 UI와 과제 조건 대조

공유된 과제6 카드·체크리스트와 과제7 조건문 기준으로, 공부 전용 문구를 일반 계획으로 바꾸거나 UI를 새로 디자인하는 것은 금지되어 있지 않습니다. 약속·생일·결혼기념일·결혼식·운동·저축·공부 등을 계획 제목과 성공 기준으로 적을 수 있습니다. 저축 금액은 성공 기준에 쓰며, 금액 집계 기능을 새로 구현했다고 주장하지 않습니다.

- T06-C04~27: 계획의 날짜·우선순위·성공 기준·예상 분, 수정 이력, 할 일 CRUD/검색/정렬, 실제 시작·끝·실행 분·막힘, 완료 중복 방지를 유지했습니다.
- T06-C28~33/C83: 계획·완료·지연·막힘 수, 예상·실제 분과 차이, 숫자에서 근거 기록으로 이동, 개선점→다음 계획을 유지했습니다.
- T06-C34~36/C78~81: 서버 저장·복원·전체 JSON 내보내기 유지. 기존 실제 자료를 예시로 덮어쓰지 않습니다. 실제 계획/할 일/기록 수는 사용자의 자료로 별도 확인해야 합니다.
- T07-C91~126/C133~134: 가입·인증·로그인·세션·소유자 검사·로그아웃·계정 삭제를 변경하지 않았습니다.
- T07의 실제 5일: 질문·지표·단위·계산 규칙 고정, 실제 다른 날짜 5개, 2일차 뒤 3일차 전 규칙 변경, 근거 ID, 합계·평균을 유지했습니다. 과거 지표는 그대로 표시하며 새 관찰만 실제 실행 시간으로 시작합니다. 단위는 계속 분입니다.
- T07-C77/C78: 제출한 과제6 고정 소스 커밋을 보존합니다. 저장소를 삭제하거나 새 저장소로 바꾸지 않습니다.

005 SQL은 새 관찰의 기본 지표 이름과 새 계정의 기본 다이어리 제목만 일반화합니다. 기존 관찰·계획·할 일·기록·ID·날짜·값에는 UPDATE/DELETE를 실행하지 않습니다. 기존 관찰이 있으면 질문·지표를 임의로 바꾸지 않습니다.

## 적용과 확인

003 적용 완료 상태에서는 005 SQL만 실행한 뒤 새 소스를 같은 저장소에 덮어써 커밋·배포합니다. 과제6 자료 귀속 004는 본인 계정 UUID를 확인한 뒤 별도로 진행합니다.

1. 로그인 → 새 계획 → 운동이나 저축 제목과 성공 기준 저장. 할 일·실행 기록 추가 후 새로고침해 값 확인.
2. 돌아보기 숫자 → 근거 기록. 예상/실제 시간과 완료 수 확인. 전체 자료 내보내기.
3. 아직 시작하지 않은 5일 관찰에서 새 지표가 실제 실행 시간/분인지 확인. 실제 사용 전 관찰을 시작하며 테스트용 날짜나 기록을 만들지 않음.

로컬 자동 검사와 화면 검사는 구현 검증입니다. 실제 배포의 메일 발송·보안 증빙·5일 실사용 완료를 대신하지 않습니다.

## 일정 입력

하루 일정은 시작일과 종료일을 같은 날짜로, 여러 날 일정은 기간으로 저장합니다. 성공 기준에는 참석·준비 목표를 적습니다. 일정만 기록하면 예상 시간을 0분으로 두고, 필요하면 준비할 일을 붙입니다. 별도 캘린더·반복 일정·알림 기능은 이번 변경에 포함되지 않습니다.
