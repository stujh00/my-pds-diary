# 이메일 인증 후 오류 화면 방지

증상: 가입 메일 링크를 누르면 `localhost:3000`으로 이동하면서 연결 오류가 보인다. 이메일 확인은 완료됐을 수 있지만 다음 이동 주소가 개발용 기본값이어서 사용자가 실패로 오해한다.

## 1. 소스 반영

기존 GitHub 저장소에 수정 파일을 같은 경로로 업로드하고 커밋한다. Vercel 재배포가 Ready가 되면 로그인 화면을 새로고침한다. 이번 수정에는 DB SQL 재실행이나 계정 재생성이 필요 없다.

수정 기능: 가입 시 현재 앱의 `/login` 주소 지정, 서버 확인 후 인증 완료 안내, 만료·이미 사용한 링크 안내, 인증 메일 다시 받기.

## 2. Supabase URL 설정

Authentication → URL Configuration:

- Site URL: `https://my-pds-diary.vercel.app`
- Redirect URLs에 정확한 경로 추가: `https://my-pds-diary.vercel.app/login`
- Save changes.

다른 배포 주소를 사용하는 경우 두 값도 해당 주소로 바꾼다. URL 설정은 GitHub 소스 업로드만으로 변경되지 않는다.

## 3. Confirm signup 메일 템플릿 설정

Authentication → Email Templates → Confirm signup을 연다. 대시보드 버전에 따라 Emails 아래 Templates 탭에 표시될 수도 있다. 제목은 `플랜두씨 이메일 인증`, 본문은 `supabase/templates/confirm-signup.html` 내용으로 교체하고 저장한다.

```html
<h2>플랜두씨 이메일 인증</h2>
<p>아래 링크를 눌러 가입한 이메일을 인증해 주세요.</p>
<p><a href="{{ .RedirectTo }}#token_hash={{ .TokenHash }}&amp;type=email">이메일 인증하기</a></p>
<p>앱 로그인 화면에 인증 결과가 표시됩니다. 인증이 완료되면 가입한 이메일과 비밀번호로 로그인해 주세요.</p>
<p>가입을 요청하지 않았다면 이 메일을 무시하셔도 됩니다.</p>
```

기본 `ConfirmationURL` 템플릿 대신 위 템플릿을 사용해야 서버 확인 후 정확한 성공/실패 안내가 나타나고 인증 서비스 JWT가 브라우저 주소에 돌아오지 않는다. 메일 발송 시점의 설정이 링크에 반영되므로 이미 받은 localhost 링크는 바뀌지 않는다. 기존 사용자 계정을 지우거나 다시 가입하지 않는다.

## 4. 실제 배포 확인

1. 새 테스트 이메일로 가입하고 새로 받은 메일에서 인증 링크를 누른다.
2. 앱 `/login`이 열리고 `이메일 인증이 완료되었습니다. 가입한 이메일과 비밀번호로 로그인해 주세요.`가 표시되는지 확인한다. 주소에 확인 값이 남지 않고 별도 비밀번호 로그인으로 기록 화면에 들어가는지도 확인한다.
3. 같은 메일 링크를 다시 열면 `인증 링크가 만료되었거나 이미 사용되었습니다.`와 로그인·재전송 안내가 나와야 한다. 이미 인증한 계정은 계속 로그인할 수 있다.

재전송: 로그인 화면에 이메일을 입력한 뒤 `인증 메일 다시 받기`를 누른다. 계정 존재 여부를 드러내지 않는 같은 안내를 표시한다. 서비스의 메일 발송 제한에 걸리면 잠시 후 다시 시도하라는 안내가 나온다.

메일과 요청 캡처에서는 링크의 확인 값도 가린다. 확인 값은 짧게 유효한 일회용 이메일 인증 값이며 자료 API의 로그인 수단이 아니다. 다이어리 API는 기존 HttpOnly 앱 세션 쿠키만 사용한다. 로컬 검사에서 성공·실패·중복 사용·값 가림을 검증했으나 실제 메일 발송과 Vercel 동작은 위 순서로 따로 확인한다.
