# 개발 환경 검증 결과

검사일: 2026-09-29. 실제 운영 Supabase 프로젝트나 Vercel 배포 계정은 연결하지 않았습니다. 아래 결과는 Node.js + 메모리 PGlite(PostgreSQL 호환 엔진) 및 Chromium에서 합성 테스트 자료로 확인한 결과입니다. 합성 테스트 자료는 제공하는 seed나 운영 DB에 포함하지 않습니다.

## 통과

- 분 단위 집계: 완료된 할 일의 지연 중복 제외, 삭제 제외, 같은 할 일의 막힘 중복 제외, 예상/실제/차이, 빈 집계 0.
- 날짜: UTC→서울 자정 경계, 서울 입력 시각→ISO UTC 변환, 마감일 기준 기간 필터.
- 정렬: 주 기준이 같으면 생성 시각, 그다음 ID 오름차순.
- SQL: 전체 스키마 설치, seed 재실행에도 계획1·할일7 유지, 실행 기록0.
- SQL: 계획 수정 뒤 최초 버전 보존, 새 버전 추가.
- 로컬 HTTP: 동일 완료 요청 2개를 동시에 보내 200/200, 완료 기록 1개 확인. 다른 Origin 요청은 403.
- SQL: 같은 요청키 재시도와 다른 키 중복 완료 모두 완료 이벤트1·현재 완료 할일1.
- SQL: 완료 취소 후 이전 완료 주기의 지연 요청 거절.
- SQL: 실행 기록 요청 재시도 중복 방지, 원래 계획/예상 분 유지.
- SQL: 돌아보기 집계와 개선점 저장, 다음 계획 연결.
- SQL: 삭제 이력 및 실행 기록을 내보내기용으로 보존.
- SQL: anon 역할의 표 및 RPC 직접 호출 거절.
- 브라우저: 할 일 생성, 제목 검색, HTML 문자열을 문자로 표시하고 이벤트 미실행.
- 브라우저: 실행 기록 저장, 완료, 새로고침 후 유지, 완료 숫자에서 근거 기록으로 이동.
- 브라우저: 돌아보기 저장 후 다음 계획에 개선점 표시.
- 브라우저: 전체 자료 JSON 다운로드.
- 브라우저: 390px 모바일 가로 넘침 없음, 검사 흐름에서 JavaScript 런타임 오류 없음.
- `npm run build` 성공, 공개 산출물은 public 파일만 복사. 서버 코드/환경 파일은 dist에 미포함.
- 이번 개발 과정에서 실제 운영 비밀키를 받거나 코드에 저장하지 않음.

## 배포 후 반드시 확인할 항목 — 미검증

- 실제 Supabase Data API와 서비스 키 연결, Vercel Function 배포 실행.
- 실제 Supabase에서 동시에 보낸 HTTP 완료 요청의 중복 방지.
- Vercel/GitHub 시크릿 창 공개 접근, 최종 전체 커밋 고정 URL.
- 사용자가 실제 공부한 실행 기록 3건 이상과 실제 관찰.
- 운영 배포 Network/Console/파일/Git 이력에 실제 키가 없는지.
- 사용자 기기에서 날짜·시간·모바일 화면, 내보내기 전후 값 비교.

화면 합계는 브라우저의 현재 시계를 서울 시간대로 변환합니다. 저장되는 돌아보기의 현재 날짜는 DB 시계를 사용합니다. 사용자 기기 시계가 틀리면 지연 수가 일시적으로 달라질 수 있으니 자동 시각 동기화를 켜세요.

`npm test`로 5개 순수 계산 검사를 재현할 수 있습니다. DB 검사는 README의 선택 검사 명령을 참고하세요. 실제 제출 근거는 `CHECKLIST.md`에 배포 후 결과를 기록해 남깁니다.
