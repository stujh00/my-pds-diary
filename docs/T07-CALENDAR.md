# 할 일 캘린더

008까지 적용한 기존 배포에서는 009 SQL만 실행하고 캘린더 수정 ZIP을 같은 GitHub 저장소에 덮어써 커밋·배포합니다. 003/004/006을 다시 실행하지 않습니다.

캘린더는 기존 서버 할 일 데이터를 읽습니다. 별도의 일정 표에 중복 복사하지 않습니다. 모든 내 계획의 할 일을 월별로 보고, 계획/상태를 필터링할 수 있습니다. 시작일·마감일을 포함하는 기간 전체에 표시합니다. 같은 할 일이 여러 날짜에 표시돼도 월별 할 일 수는 한 번만 셉니다. 완료·마감 지남 색상을 구분하고 삭제된 할 일은 제외합니다.

현재 코드의 기존 할 일에는 마감일만 있었습니다. 009는 nullable `pds_tasks.start_date` 항목과 시작일<=마감일 제약을 추가합니다. 기존 ID·마감일·값·단위·revision·updated_at을 변경하지 않으며 과거 시작일을 임의 생성하지 않습니다. 시작일 없는 기존 할 일은 마감일에 표시합니다. 수정 화면에서 시작일을 직접 저장하면 기간 표시를 시작합니다. 시작일·마감일이 같으면 하루 일정으로 표시됩니다.

날짜를 누르면 그날의 전체 할 일과 연결된 계획을 봅니다. 셀에는 최대 두 개의 제목을 표시하고 나머지는 ‘+N개 더’로 연결합니다. 제목을 누르면 해당 계획의 할 일 화면으로 이동합니다. 날짜별 목록에서 수정·완료·실행 기록을 남길 수 있습니다. 달력에서 추가하면 선택한 날짜를 시작일/마감일 기본값으로 넣고 연결할 계획을 선택합니다. 저장·수정·완료·삭제 결과는 같은 서버 자료에서 다시 읽어 반영합니다.

돌아보기의 기간 집계는 기존처럼 할 일 마감일 기준입니다. 달력의 기간 겹침 표시가 과제6 집계나 과제7 실제 실행 기록·5일 관찰 규칙을 바꾸지 않습니다. 인증·소유자 검사·내보내기를 유지하며 내보내기에도 시작일이 포함됩니다.

## 짧은 확인 방법

- 어디로 가나요: 로그인 → 캘린더.
- 세 단계 안에 무엇을 하나요: 날짜 클릭 → 할 일 추가 → 계획·제목·시작일·마감일 저장.
- 무엇이 보이면 통과인가요: 해당 기간의 달력에 제목이 나타남. 다른 달 이동·계획/상태 필터·제목→할 일 이동 가능. 날짜 수정 또는 완료 후 바로 반영되고 새로고침 뒤 같은 값 유지.
- 안 될 때 무엇이 보이나요: 마감일이 시작일보다 빠르면 모달 오류. SQL 누락/서버 문제는 DB 요청 오류. 자료가 없는 날짜는 빈 목록, 시작일 없는 기존 할 일은 마감일에만 표시.

검사는 [테스트] 계획으로 진행하고, 과제7 실제 5일 기록용 실행 자료와 구분합니다. 화면 미리보기의 [예시] 자료는 로컬 UI 검사 자료이며 사용자 서버 DB에 저장하지 않았습니다.
